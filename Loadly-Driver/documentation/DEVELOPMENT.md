# Development guide

Practical notes for working on Loadly Driver. Architecture detail is in [ARCHITECTURE.md](ARCHITECTURE.md). Runtime problems are in [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## Prerequisites

- [FVM](https://fvm.app/)
- Flutter **3.41.2** (pinned in `.fvmrc`)
- Dart SDK `^3.8.0` (from `pubspec.yaml`; the FVM Flutter SDK supplies it)
- Android: Android SDK, JDK 17 (the GitHub workflow uses Temurin 17; `android/app/build.gradle.kts` targets Java 17)
- iOS: Xcode, CocoaPods, and a Mac (not verified from this Windows workspace)
- Firebase config files already used by the app:
  - `android/app/google-services.json`
  - `ios/Runner/GoogleService-Info.plist`

VS Code / Cursor reads the SDK from `.fvm/flutter_sdk` (`.vscode/settings.json`). `.fvmrc` sets `updateVscodeSettings` to false, so FVM will not overwrite that file.

## Install

```bash
fvm install
fvm flutter pub get
fvm dart run build_runner build --delete-conflicting-outputs
```

Localization is generated by Flutter (`flutter: generate: true`, `l10n.yaml`). `pub get` / `flutter gen-l10n` refreshes `lib/l10n/gen/`. Do not edit generated `*.g.dart` or `lib/l10n/gen/` by hand.

## Run

```bash
fvm flutter run
```

The default API base URL is the staging driver API compiled into `lib/core/network/api_client.dart`. Override it at compile time:

```bash
fvm flutter run --dart-define=DRIVER_API_BASE_URL=https://stg-api-agg.loadly-eg.com/api/driver
```

Pass the same `--dart-define` flags for Maps, Sentry, and store links when you are not using the values compiled into source. See [Configuration](#configuration).

`lib/main.dart` imports `dart:io`, so `flutter run -d chrome` is not a supported entrypoint. **Needs clarification** for macOS, Windows, and Linux: platform folders exist, CI only builds an Android APK.

## Build

Android APK (same command as CI, which does not pass dart-defines):

```bash
fvm flutter build apk --release
```

Example with an explicit API and store channel:

```bash
fvm flutter build apk --release ^
  --dart-define=DRIVER_API_BASE_URL=https://example.com/api/driver ^
  --dart-define=APP_STORE_DISTRIBUTION=play
```

iOS (on macOS):

```bash
fvm flutter build ipa --dart-define=IOS_APP_STORE_ID=YOUR_NUMERIC_ID
```

Huawei AppGallery-style defines (from `AppStoreConfig`; the app does not detect Huawei devices by itself):

```bash
fvm flutter build apk --release ^
  --dart-define=APP_STORE_DISTRIBUTION=harmonyos ^
  --dart-define=HUAWEI_APP_GALLERY_ID=YOUR_ID
```

Release signing still uses the debug keystore in `android/app/build.gradle.kts`.

Launcher icons and native splash are configured in `pubspec.yaml` (`flutter_launcher_icons`, `flutter_native_splash`). Regenerate only when those assets change:

```bash
fvm dart run flutter_launcher_icons
fvm dart run flutter_native_splash:create
```

CI: `.github/workflows/build-apk.yml` on push to `main` and `workflow_dispatch`. It builds a release APK, uploads it to S3, and notifies email and Teams. Secrets (`S3_BUCKET`, `TEAMS_WEBHOOK_URL`, SES) are configured in GitHub, not in the repo.

## Configuration

The running app reads **compile-time** `--dart-define` values. The `dotenv` package is unused. A `.env` file in the repo root is not loaded by Dart and is not listed in `.gitignore`. Do not put new secrets there unless the team agrees to ignore it. **Needs clarification** what `.env` is for.

| Define | Where it is read | If omitted |
| --- | --- | --- |
| `DRIVER_API_BASE_URL` | `lib/core/network/api_client.dart` | Staging URL hardcoded as `defaultValue` |
| `SENTRY_DSN` | `lib/main.dart` | DSN hardcoded as `defaultValue`. Sentry still runs only in release mode. |
| `GOOGLE_MAPS_API_KEY` | `lib/core/config/google_maps_config.dart` | Key hardcoded as `defaultValue` (Geocoding / Directions REST). The Android Maps SDK key is a separate literal in `android/app/src/main/AndroidManifest.xml`. iOS provides a key from native code (`GMSServices.provideAPIKey` in `ios/Runner/AppDelegate.swift`). |
| `IOS_APP_STORE_ID` | `lib/core/config/app_store_config.dart` | Empty; iOS update link falls through |
| `HUAWEI_APP_GALLERY_ID` | same | Empty |
| `APP_STORE_DISTRIBUTION` | same | `play` |
| `APP_STORE_URL` | same | Empty; platform default is used |

`AppStoreConfig.storeUrl` order: `APP_STORE_URL`, else iOS App Store when the id is set, else AppGallery when the distribution is `harmonyos` or `appgallery` and an id is set, else Play Store `com.loadly.driver`.

Google Maps REST usage notes that are already in `google_maps_config.dart`: Android/iOS app restrictions on a key often do not apply to Web Service REST the same way as the Maps SDK. Billing and quota limits are set in Google Cloud, not in this repo.

## Where to put new code

Follow an existing feature. Auth is the fullest example.

| Piece | Location |
| --- | --- |
| Screen | `lib/features/<feature>/presentation/views/` |
| Feature widget | `lib/features/<feature>/presentation/widgets/` |
| BLoC, events, states | `lib/features/<feature>/presentation/bloc/` |
| Entity | `lib/features/<feature>/domain/entities/` |
| Repository interface | `lib/features/<feature>/domain/repositories/` |
| Use case | `lib/features/<feature>/domain/use_cases/` |
| Failure type | `lib/features/<feature>/domain/failures/` |
| DTO (`@JsonSerializable`) | `lib/features/<feature>/data/models/` |
| HTTP calls | `lib/features/<feature>/data/sources/remote/` |
| Repository implementation | `lib/features/<feature>/data/repositories/` |
| Shared widget, theme, network, storage | `lib/core/...` |
| Route | `lib/core/router/app_router.dart` |
| Endpoint constant | `lib/core/network/api_endpoints.dart` |
| English/Arabic copy | `lib/l10n/app_en.arb`, `lib/l10n/app_ar.arb` |
| Widget or unit test | `test/`, mirroring the `lib/` area when practical |

Profile and settings do not have data/domain layers. Profile uses auth use cases. Do not add a second profile API client unless the endpoint is new.

## How to add a feature

1. Add the endpoint constant in `ApiEndpoints`.
2. Add a DTO with `@JsonSerializable` and run build_runner.
3. Add an entity if the UI should not depend on JSON field names.
4. Add a repository method returning `Either<YourFailure, T>`. Implement it with `safeApiCall` (see `AuthImpl`).
5. Add a use case that only forwards to the repository.
6. Handle a new event on the feature BLoC, or add a BLoC if the feature is new.
7. Construct the data source, repository, use case, and BLoC in `lib/main.dart` and add the BLoC to `MultiBlocProvider`. Do not register it only in `get_it` unless you are extending the existing trips exception (`service_locator.dart`).
8. Add a `GoRoute`. If the screen requires login, leave it out of the `isAuthRoute` list in `createAppRouter`. If it is part of login/OTP, add it to that list.
9. If the screen is a main tab, wrap it with `MainScaffold` and extend `AppBottomNavBar` indexes. Current indexes are profile 0, notifications 1, trips 2, home 3.
10. Add strings to both ARB files.
11. Add a unit test for parsing or pure logic. Widget tests that construct `LoadlyDriverApp` must supply blocs the way `test/widget_test.dart` does, or pump a smaller widget.

## Coding conventions found in the project

- `prefer_relative_imports` and `prefer_const_constructors` are enabled in `analysis_options.yaml`, on top of `flutter_lints`.
- UI is Cupertino (`CupertinoPageScaffold`, `CupertinoButton`, and so on).
- Domain failures are `equatable` classes. Auth failures are a `sealed class`.
- Repository methods return `Future<Either<Failure, T>>`.
- JSON models use `json_serializable`, not hand-written `fromJson`, and not Freezed (Freezed is unused).
- User-visible strings go through `AppLocalizations`. Some failure mappers still return raw English fallbacks or l10n **keys** (`auth.network_error`) that the UI must translate.
- Phone numbers sent to auth APIs are normalized with a `+2` prefix in `AuthImpl` and in settings (`_loginFromProfile`).
- Comments that explain a non-obvious workaround are already in the file (map renderer, 401 on auth screens, Chucker navigator key). Match that style: say why, not what the next line does.

## Common development problems

See [TROUBLESHOOTING.md](TROUBLESHOOTING.md). Short versions:

- After changing a `@JsonSerializable` class, run build_runner. Stale `*.g.dart` will not match the model.
- After adding a plugin (ML Kit is called out in `odometer_image_validator.dart`), hot reload can throw `MissingPluginException`. Stop the app and run it again.
- `AuthStorage.init()` must run before any token read. Tests and new entrypoints that touch the API need that, or a token will be missing.
- Two Dio clients exist (see ARCHITECTURE). A change to interceptors in `createDriverApiClient` applies to both only because both call that function. `AuthStorage` uses a third Dio with no interceptors for refresh.
